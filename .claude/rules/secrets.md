# 機密情報の取り扱い

secrets・アクセストークン・API キー・パスワードなど、漏洩すると第三者が外部リソースを操作できるようになる値を対象とする。以下ではこれらを「実値」と呼ぶ。

このリポジトリは現状 GitHub Actions の secrets を使っていない。npm への公開は GitHub OIDC の Trusted Publishing(`permissions: id-token: write` と `pnpm publish --provenance`)で行っており、npm トークンを保持していない。この前提を壊す変更 — 公開フローを token 方式へ戻す、secrets を新規に導入する — は、`CLAUDE.md` の「設計フェーズに入る条件」にいう権限の変更にあたる。

## 実値を書かない場所

- git 管理対象のファイル全般。実値を置いてよいのは gitignore 済みのローカルファイルと、各サービスの secret ストア(GitHub / npm)だけ
- コミットメッセージ、PR のタイトル・本文
- `ai-communication/result_*.md` / `review_*.md`。git 管理外だが平文でローカルに残り、AI 間で受け渡される
- チャットへの応答、およびコマンドの実行結果として出力するログ

これらに書いてよいのは変数名と取得元(どのサービスの secret に登録されているか)だけで、値そのものは書かない。値を含む手順を説明する場合も `<YOUR_TOKEN>` のようなプレースホルダに置き換える。

## CI/CD での最小公開範囲

- secrets・環境変数は必要なジョブ/ステップにのみ渡す。ワークフローの top-level `env:` には置かない
- `permissions:` は既定を `contents: read` とし、必要なジョブでのみ広げる(現状 `id-token: write` は CD ワークフローのみ)
- CI 専用の捨て値(漏れても実害の無い値)をワークフローに直書きする場合は、捨て値である旨をコメントで明記する

## 実値を書いてしまった場合

- push 前に気づいた場合はコミットを作り直す
- push 済み、または外部サービスへ送信済みの場合は、履歴の修正より先に値をローテーション(無効化・再発行)する。履歴を消しても、取得された可能性そのものは消えない
